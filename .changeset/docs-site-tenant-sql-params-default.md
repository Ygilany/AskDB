The docs say `tenantSqlMode` defaults to `"sql-params"`, and that hosts run `result.sql` with `result.tenantParams` (the core and client API references, the multi-tenancy, embed-in-node and run-safely-in-prod guides, and `/AGENTS.md`). The `TenantSqlOutputMode` reference no longer says `sql-params` uses Postgres `$N` markers on every dialect (#320). Safety boundaries and the core API reference say an inlined tenant ID must be printable ASCII without a backslash, on every dialect, and that a custom `AskDialect` with a tenant scope must set `tenantSqlMode`. Safety boundaries also explains the `sjis` / `cp932` / `ujis` connection-charset case for drivers that interpolate on the client. Troubleshooting gains `UNESCAPABLE_TENANT_ID`, `TENANT_SQL_MODE_REQUIRED` and the driver error a host sees when it runs the new `sql` without its params. The beta.45 upgrade notes gain both breaking changes: running tenant-scoped SQL with its `tenantParams`, and `sql-params` for tenant IDs outside printable ASCII.
