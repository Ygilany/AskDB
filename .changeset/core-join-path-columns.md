A join counts in the tenant check only on the columns the policy declares (#400). A table scoped through a join path needs each hop to equate the declared columns (`appointments.client_id = clients.id`), as a `col = col` conjunct or `col IN (SELECT col …)` on the reads joined, in the same `SELECT`, up to a read filtered with an allowed root's placeholder. A root the scope covers, filtered through another table's column, needs the join on its ID column. A join on any other pair of columns links nothing. A scoped table's tenant column joined to a filtered root's ID, or `IN (SELECT id FROM <root> WHERE id = :p)`, now passes.

Upgrade notes (breaking): SQL that passed before and now throws `TenantGuardrailError` (`MISSING_TENANT_PREDICATE`) under `strict`: a join-path table joined on other columns or not joined, a covered root cross-joined or joined on another column to a filtered table, a join through a CTE or derived table, or to a source that only borrows a table's name, which the check doesn't follow; `col IN (SELECT …)` that carried a predicate out of its subquery (`id IN (SELECT id FROM orders WHERE agency_id = :p)`); and, in a `SELECT` with an outer join, a tenant predicate or a join-path equality in any `ON` (`appointments a LEFT JOIN clients c ON a.client_id = c.id WHERE c.id IN (…)`), since the outer join keeps rows an `ON` never matched. Join on the declared columns in the same `SELECT` (`JOIN` where `WHERE` filters the joined side), or filter the read where it is. Under `sqlite`, an `ON` that relies on a comma-joined or later-joined read is refused: write the join out, or move the predicate to `WHERE`.
