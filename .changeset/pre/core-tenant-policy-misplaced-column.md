The tenant-policy loader refuses a column on another table than its entry's (#836). It checked only that `schema.json` had each column somewhere, so a `scopeThrough` column, a polymorphic `typeColumn` or `idColumn`, a root's `tenantIdColumn` or `parent.foreignKey`, or a hierarchy edge's `foreignKey` written as another table's column loaded with no warning, even under `enforcement: strict`, and broke that table's filter path. Such a column is now the new `TenantPolicyWarning` `misplaced_column_id` (`id`, `tableId`, the table the column is on, and `context`): an error under `strict`, which makes `loadSchema()` throw `SchemaParseError`, and a warning under `warn`. A `switch` over every `TenantPolicyWarning` needs a case for it. `normalizeTenantPolicy()`'s third parameter is now a `ReadonlyMap` from column ID to table ID instead of a `Set` of column IDs, since a column's table comes from `schema.json`, not from splitting its ID (a SQL Server table name can hold `#`). Join paths aren't checked step by step yet (#837).
