<p class="doc-eyebrow">Reference · Configuration</p>

<p class="doc-lede">AskDB resolves config from two sources: an <code>askdb.config.*</code> file (TypeScript or JavaScript) and environment variables. Both are loaded by <code>@askdb/config</code> at startup into an in-memory runtime snapshot.</p>

## `askdb.config.ts`

`askdb init` scaffolds this file. It uses `defineConfig` for type safety:

```ts
import { defineConfig, env } from "@askdb/config";

export default defineConfig({
  ai: {
    provider: "openai",
    providerConfig: {
      openai: { apiKey: env("OPENAI_API_KEY") },
    },
    language: { model: env("OPENAI_MODEL") },
    embedding: { model: "text-embedding-3-small" },
  },
  introspection: {
    provider: "postgres",
    providerConfig: {
      postgres: { databaseUrl: env("DATABASE_URL") },
    },
    outputDir: "./my-app.schema",
  },
  rag: {
    embedder: "ai",
    store: "pgvector",
    storeConfig: {
      pgvector: { databaseUrl: env("PGVECTOR_URL") },
    },
  },
  logging: {
    level: "info",
  },
});
```

Use the `env()` helper (rather than `process.env`) so AskDB can capture which environment variables your config depends on and apply its defaults pass.

`defineConfig` returns the object unchanged at runtime — it exists only for type inference. The full type is `AskDbConfig`.

## All top-level fields

| Field | Required | What it configures |
| --- | --- | --- |
| `ai` | yes | Provider connections (`provider`, `providerConfig`), the language model (`language`) and the embedding model (`embedding`). See [The `ai` block](#the-ai-block) and [Bring your own model](/guides/bring-your-own-model/). |
| `introspection` | yes | Introspection engine (`provider`: `postgres`, `mysql`, `sqlite`, `sqlserver`, `prisma`), its connection (`providerConfig`), `outputDir` (default `./askdb/`), and optionally `schemas`: the schemas to introspect, like `askdb introspect --schemas` (which overrides it). On MySQL/MariaDB these are databases. |
| `rag` | yes | Embedder (`mock`, or `ai` for the `ai.embedding` model) and vector store (`file`, `memory`, `pgvector`) plus the store's config branch. See [The `rag` block](#the-rag-block). |
| `dialect` | no | Override the NL-to-SQL dialect (`postgres`, `mysql`, `sqlite`, `sqlserver`). When unset, it's inferred from the schema artifact's recorded provider. |
| `modes` | no | `askdbMode` (`schema_only` default, `bounded_results`) and `omitSensitiveFromPrompt` (default `false`). |
| `host` | no | `schemaPath` — the default schema artifact for embedding hosts and the HTTP API. `schemaJson` — inline artifact JSON, for environments without a file system path. |
| `logging` | no | `level`, plus `logFile`, `logStdout`, and `correlationId` defaults for the CLI's structured logs. |
| `studio` | no | `listen.{host,port}` (defaults `127.0.0.1:5556`) and the `execute` block below. |
| `httpApi` | no | `listen.{host,port}` for the HTTP API server (defaults `127.0.0.1:3000`). Use `env("PORT")` on platforms that inject a port. |
| `dev` | no | `mockSql` — deterministic NL-to-SQL output for tests; bypasses the model call. |

### `dialect` — when inference is wrong

The dialect normally resolves from the schema artifact (the engine recorded at introspection time). Set `dialect` only when that inference is wrong — for example, a Prisma schema that declares `provider = "postgresql"` while your runtime target is a different engine:

```ts
export default defineConfig({
  // ...
  dialect: "mysql",
});
```

### `modes` and `host`

```ts
export default defineConfig({
  // ...
  modes: {
    askdbMode: "schema_only",        // default
    omitSensitiveFromPrompt: true,   // strict sensitive-column handling
  },
  host: {
    schemaPath: "./my-app.schema",   // default artifact for embedding + HTTP API
  },
});
```

## The `ai` block

`ai` separates *how to reach a provider* from *which model to use for what*:

- **`ai.providerConfig`** holds provider connections: keys, endpoints, Azure resources, API versions. No model names.
- **`ai.language`** picks the language model AskDB writes SQL and enrichment suggestions with.
- **`ai.embedding`** picks the embedding model behind `rag.embedder: "ai"`.
- **`ai.provider`** is the default provider for both sections.

A section's provider is its own `provider`, else `ai.provider`. Its connection is its own `connection`, else the connection named `"default"` within that provider. Loading fails when a section has no provider, names a connection that doesn't exist, or uses a built-in provider with no connection at all. Each section only ever receives its own connection's settings, so a key configured for one provider is never sent to another.

Anthropic for SQL, OpenAI for embeddings:

```ts
export default defineConfig({
  ai: {
    provider: "anthropic",
    providerConfig: {
      anthropic: { apiKey: env("ANTHROPIC_API_KEY") },
      openai: { apiKey: env("OPENAI_API_KEY") },
    },
    language: { model: "claude-sonnet-4-6" },
    embedding: { provider: "openai", model: "text-embedding-3-small" },
  },
  rag: { embedder: "ai", store: "file", storeConfig: { file: {} } },
  // ...
});
```

Two Azure resources, one for each model:

```ts
export default defineConfig({
  ai: {
    provider: "azure",
    providerConfig: {
      azure: [
        { resourceName: "eastus-chat", apiKey: env("AZURE_CHAT_KEY") },                  // name: "default"
        { name: "westus", resourceName: "westus-embed", apiKey: env("AZURE_EMBED_KEY") },
      ],
    },
    language: { model: "my-gpt-4o-deployment", modelFamily: "gpt-4o" },
    embedding: { connection: "westus", model: "my-embedding-deployment", dimensions: 1536 },
  },
  rag: { embedder: "ai", store: "pgvector", storeConfig: { pgvector: { databaseUrl: env("PGVECTOR_URL") } } },
  // ...
});
```

### `ai.providerConfig`

Keyed by provider id. Each value is one connection, or a list of connections when a provider needs more than one.

| Provider key | Connection fields |
| --- | --- |
| `openai` | `apiKey`, `baseUrl` (any OpenAI-compatible endpoint) |
| `azure`, `foundry` | `apiKey`, `secondaryApiKey`, `resourceName` (the subdomain of `https://<name>.openai.azure.com`), `baseUrl` (a full endpoint URL; overrides `resourceName`), `apiVersion`. One of `resourceName` or `baseUrl` is required. |
| `anthropic` | `apiKey`, `baseUrl` |
| `google` | `apiKey`, `baseUrl` |
| `gateway` | `apiKey`, `baseUrl` (Vercel AI Gateway) |
| any other id | `apiKey`, `baseUrl`, for a [custom provider](#custom-providers) |

Every connection also takes `name`, which defaults to `"default"` and must be unique within its provider. For a built-in provider, a list needs a `"default"` entry unless every section that uses the provider sets `connection`.

### `ai.language`

| Field | Default | Notes |
| --- | --- | --- |
| `provider` | `ai.provider` | |
| `connection` | `"default"` | A connection name in `ai.providerConfig.<provider>`. |
| `model` | The provider's default language model | `openai`: `gpt-4o-mini`. `anthropic`: `claude-sonnet-4-6`. `google`: `gemini-2.0-flash`. `gateway`: `openai/gpt-4o-mini`. `azure` and `foundry`: the deployment name, default `gpt-4o-mini`. A custom provider has no default. |
| `modelFamily` | none | Azure and Foundry: the underlying model id when `model` is a deployment name. See [Azure deployment names](#azure-deployment-names). |
| `reasoning` | none | See [Reasoning effort](#reasoning-effort). |

### `ai.embedding`

Read only when `rag.embedder` is `"ai"`; ignored for `"mock"`.

| Field | Default | Notes |
| --- | --- | --- |
| `provider` | `ai.provider` | Anthropic has no embeddings API, so a config whose `ai.embedding` provider resolves to `anthropic` fails to load. Set `provider` (for example `"openai"`) and give it a connection. |
| `connection` | `"default"` | A connection name in `ai.providerConfig.<provider>`. |
| `model` | none, required | AskDB has no default embedding model. On Azure, the embedding deployment name. On the AI Gateway, an `<upstream>/<model>` id such as `openai/text-embedding-3-small`. |
| `dimensions` | The model's known width | A positive integer, sent to the provider as the requested vector size. AskDB knows `text-embedding-3-small` (1536), `text-embedding-3-large` (3072) and `text-embedding-ada-002` (1536) on `openai`, `azure` and `foundry`, and their `openai/…` ids on `gateway`. For any other model with the `pgvector` store, set it: pgvector needs a fixed width. |

Changing the `ai.embedding` provider, model or dimensions changes the index's embedder id: Studio then reports the RAG index as stale and asks you to reindex before using it.

### Reasoning effort

`ai.language.reasoning` is an optional, provider-portable knob for how much reasoning/thinking effort AskDB's model calls use. Leave it unset to keep the provider/model's own default (AskDB sends no reasoning options at all — this is the default, unchanged behavior).

```ts
export default defineConfig({
  ai: {
    provider: "openai",
    providerConfig: { openai: { apiKey: env("OPENAI_API_KEY") } },
    language: {
      reasoning: {
        effort: "medium",     // global default for every AskDB model call
        nlToSql: "high",      // override: accuracy-sensitive NL→SQL generation
        enrichment: "low",    // override: non-critical enrichment suggestions
      },
    },
  },
  // ...
});
```

- `effort` — global default. One of `"minimal" | "low" | "medium" | "high"`.
- `nlToSql` — overrides `effort` for NL→SQL generation calls (`ask()`). Typically left unset (provider default) or `"medium"`/`"high"` — this path is accuracy-sensitive.
- `enrichment` — overrides `effort` for enrichment/suggestion calls (`suggestEnrichment()`). Safe to bias toward `"low"`/`"minimal"` for latency and cost — these are non-critical.

AskDB maps the portable value to each provider's native knob via `@askdb/ai`'s `resolveProviderOptions` — OpenAI/Azure `providerOptions.openai.reasoningEffort`, Google Gemini 3.x `providerOptions.google.thinkingConfig.thinkingLevel`, Gemini 2.5 `thinkingConfig.thinkingBudget`, Anthropic `thinking` (adaptive thinking plus `effort` on Claude Sonnet 4.6, Opus 4.6 and newer, and the 5.x models; a `budgetTokens` budget on Claude 3.7 Sonnet and the 4.0–4.5 models). Models that don't support reasoning tuning (e.g. `gpt-4o-mini`, `gpt-5-chat-latest`, `gemini-2.0-flash`, `claude-3-5-haiku`) never receive these options, even when `reasoning` is set. Where a model has no `minimal` level, AskDB sends `low` instead: OpenAI and Azure gpt-6 and later (which accept `low` through `max`), and Anthropic models that take `effort`. For the Vercel AI Gateway (`gateway`), AskDB uses the mapping of the model's upstream (`openai/…`, `google/…`, `anthropic/…`) on the id after the prefix, and the gateway passes the options on; models from other upstreams get no reasoning options.

`@askdb/client`'s `createAskDb` resolves `ai.language.reasoning` automatically for `ask()` calls — no extra wiring needed. See [Bring your own model](/guides/bring-your-own-model/) for the client and programmatic APIs.

### Azure deployment names

Azure identifies models by deployment name (e.g. `askdb-reporting`), which may not match the underlying model id AskDB uses to detect reasoning support. Set `ai.language.modelFamily` (or `ASKDB_AI_AZURE_MODEL_FAMILY`) to the real model id — e.g. `"gpt-5"` or `"o3-mini"` — when your deployment name doesn't already look like one.

## The `rag` block

| Field | What it configures |
| --- | --- |
| `embedder` | `"mock"`, a deterministic lexical embedder that needs no key, or `"ai"`, the [`ai.embedding`](#aiembedding) model. |
| `store` | `"file"`, `"memory"` or `"pgvector"`. |
| `storeConfig` | The selected store's branch: `file.{basePath, autoFlush}`, `memory: {}`, or `pgvector.{databaseUrl, table, indexStrategy, dimensions}`. |

With `embedder: "ai"`, the pgvector table's width is the embedding model's (`ai.embedding.dimensions`, or the width AskDB knows for the model). `storeConfig.pgvector.dimensions` sets the width for `embedder: "mock"` (default 64); with `embedder: "ai"` it's [deprecated](#deprecated-keys).

## Deprecated keys

Configs written before the `ai.language` and `ai.embedding` sections still load, apart from the few cases below that fail with an error saying what to change. AskDB translates each old key at load and warns once per key with a Node `DeprecationWarning` (code `ASKDB_CONFIG_DEPRECATED`). The warning names the old and new location, never the value. `getAskDbRuntimeConfig().deprecations` lists the same messages. The old keys are removed at 1.0.

| Old key | Use instead |
| --- | --- |
| `ai.providerConfig.<provider>.model` | `ai.language.model` |
| `ai.providerConfig.azure.modelFamily`, `ai.providerConfig.foundry.modelFamily` | `ai.language.modelFamily` |
| `ai.reasoning` | `ai.language.reasoning` |
| `ai.providerConfig.custom` | `ai.providerConfig.<provider id>` |
| `rag.embedder: "openai"` | `rag.embedder: "ai"` with `ai.embedding: { provider: "openai", model }` |
| `rag.embedder: "ai-sdk"` | `rag.embedder: "ai"` with `ai.embedding: { model }` |
| `rag.embedderConfig.openai.model`, `.dimension` | `ai.embedding.model`, `ai.embedding.dimensions` |
| `rag.embedderConfig.openai.apiKey`, `.baseUrl` | A connection in `ai.providerConfig`, named in `ai.embedding.connection` if it isn't the default one |
| `rag.storeConfig.pgvector.dimensions` with an AI embedder | `ai.embedding.dimensions` |

How the old embedder keys translate:

- A model left unset means `text-embedding-3-small` on `openai`, `azure` and `foundry`, as before. Any other provider fails to load and asks for `ai.embedding.model`.
- `"ai-sdk"` embeds with the language model's provider, so with Anthropic, which has no embeddings API, it fails to load: move to `ai.embedding` with another provider.
- A model AskDB doesn't know keeps the 1536-wide vectors the old embedders assumed, so an existing index keeps its embedder id. Set `ai.embedding.dimensions: 1536` when you migrate.
- A `rag.embedderConfig.openai.apiKey` or `.baseUrl` that differs from the default connection of the embedding model's provider moves to a connection named `"rag-embeddings"`. It can only move to an `openai`, `azure`, `foundry` or `gateway` connection; with any other embedding provider the config fails to load instead of sending the key there.
- An empty `rag.embedderConfig: {}`, which earlier scaffolds wrote, is ignored without a warning.

A model set in both places is fine: `ai.language.model` wins, and the warning says the old value is ignored. Other old keys set next to their replacement fail to load, and the error asks you to remove the old one: `ai.reasoning` with `ai.language.reasoning`, `ai.providerConfig.custom` with `ai.providerConfig.<provider id>`, `rag.embedderConfig` with `ai.embedding` or `rag.embedder: "ai"`, and two different widths in `rag.storeConfig.pgvector.dimensions` and the embedding section.

## File discovery

`bootstrapAskDbEnv()` looks for config in the **current working directory only** (no upward walk), trying two locations in order:

1. `askdb.config.<ext>` — extension precedence `ts → mts → cts → js → mjs → cjs`
2. `.config/askdb.<ext>` — same extension precedence

The first match wins. JSON config files are not supported. If nothing is found, `bootstrapAskDbEnv()` throws — run your process from the directory that holds the config (or pass `cwd` in its options).

## Environment variables

AskDB reads `.env` next to your process via `dotenv`, then evaluates your `askdb.config.*`. **You choose the variable names** — they're whatever you pass to `env("…")` in your config. The scaffolded config uses these common names; rename any of them in your config and `.env` together:

| Variable | Reads into (config field) | Notes |
| --- | --- | --- |
| `OPENAI_API_KEY` | `ai.providerConfig.openai.apiKey` | Standard OpenAI key. |
| `OPENAI_MODEL` | `ai.language.model` | Optional model override. Default: `gpt-4o-mini`. |
| `ANTHROPIC_API_KEY` | `ai.providerConfig.anthropic.apiKey` | When `ai.provider = "anthropic"`. Default model: `claude-sonnet-4-6` (the scaffolded config reads an `ai.language.model` override from `ANTHROPIC_MODEL`). |
| `GOOGLE_GENERATIVE_AI_API_KEY` | `ai.providerConfig.google.apiKey` | When `ai.provider = "google"`. Default model: `gemini-2.0-flash` (the scaffolded config reads an `ai.language.model` override from `GOOGLE_AI_MODEL`). |
| `AI_GATEWAY_API_KEY` | `ai.providerConfig.gateway.apiKey` | When `ai.provider = "gateway"` (Vercel AI Gateway). Set `ai.language.model` to an `<upstream>/<model>` id. Default: `openai/gpt-4o-mini`. An id without the prefix is rejected when the model is built, and that includes `ai.embedding.model`: use e.g. `openai/text-embedding-3-small`. Embedding `dimensions` are sent for `openai/` and `google/` models; for other upstreams a dimension override is refused rather than dropped. |
| `AZURE_OPENAI_API_KEY` | `ai.providerConfig.azure.apiKey` | When `ai.provider = "azure"` (use `ai.providerConfig.foundry` for `"foundry"`). |
| `AZURE_OPENAI_DEPLOYMENT` | `ai.language.model` | Your Azure deployment name. |
| `AZURE_RESOURCE_NAME` | `ai.providerConfig.azure.resourceName` | The subdomain of `https://<name>.openai.azure.com`. Required unless you set `ai.providerConfig.azure.baseUrl` to a full endpoint URL instead. Also available on the connection: `apiVersion`, `secondaryApiKey`. |
| `DATABASE_URL` | `introspection.providerConfig.postgres.databaseUrl` | Postgres introspection connection. |

Everything else AskDB needs — output directory, mode, log level, Studio query connection, the vector-store URL — is set the same way: a field in `askdb.config.ts`, bound to a name you choose with `env("…")`. You don't set any AskDB-prefixed variables yourself; AskDB derives its internal runtime values from your config.

## Studio execute configuration

The `studio.execute` block configures the Query Playground's live execution feature. It is **off by default**: set `enabled: true` and give Studio its own connection, ideally for a read-only database role.

```ts
export default defineConfig({
  studio: {
    execute: {
      enabled: true,
      provider: "mysql",                       // "postgres" | "mysql" | "sqlite" | "sqlserver"
      databaseUrl: env("STUDIO_READONLY_URL"), // network databases (Postgres, MySQL, SQL Server)
      // file: env("SQLITE_FILE"),             // SQLite only
      // timeoutMs: 30000,
      // maxRows: 500,
    },
  },
});
```

| Field | Env key | Default |
|---|---|---|
| `studio.execute.enabled` | `ASKDB_STUDIO_EXECUTE_ENABLED` | `false`. While off, `POST /api/execute` returns `403` and the Playground hides Execute. |
| `studio.execute.provider` | `ASKDB_STUDIO_EXECUTE_PROVIDER` | Active introspection provider, or `"postgres"` |
| `studio.execute.databaseUrl` | `ASKDB_STUDIO_DATABASE_URL` | None (see `useIntrospectionConnection`) |
| `studio.execute.file` | `ASKDB_STUDIO_SQLITE_FILE` | None (see `useIntrospectionConnection`) |
| `studio.execute.useIntrospectionConnection` | `ASKDB_STUDIO_EXECUTE_USE_INTROSPECTION_CONNECTION` | `false`. When `true`, reuse the introspection connection if `databaseUrl` / `file` is unset. |
| `studio.execute.timeoutMs` | `ASKDB_STUDIO_EXECUTE_TIMEOUT_MS` | `30000`. Per-query timeout, positive integer. Not enforced for SQLite. |
| `studio.execute.maxRows` | `ASKDB_STUDIO_EXECUTE_MAX_ROWS` | `500`. Row cap, positive integer. Results with more rows are truncated. |

**Provider resolution order:**

1. `studio.execute.provider` (structured config or `ASKDB_STUDIO_EXECUTE_PROVIDER` env).
2. The active `introspection.provider` when it is a live engine (`postgres`, `mysql`, `sqlite`, `sqlserver`).
3. `"postgres"` for backward compatibility.

**Connection resolution** (per provider):

- **Postgres, MySQL, SQL Server**: `studio.execute.databaseUrl` → `ASKDB_STUDIO_DATABASE_URL` → the introspection URL for the same engine, only when `useIntrospectionConnection: true`.
- **SQLite**: `studio.execute.file` → `ASKDB_STUDIO_SQLITE_FILE` → the introspection SQLite file, only when `useIntrospectionConnection: true`.

Studio doesn't fall back to your introspection credentials on its own, because those usually belong to a more privileged role than ad-hoc queries should use. [Studio — Security model](/studio/#security-model) describes the read-only transaction, timeout, and row cap applied to every query.

Each execute provider requires its optional peer driver package (`pg`, `mysql2`, `better-sqlite3`, or `mssql`). See [Studio — driver packages](/studio/#driver-packages) for install instructions.

## Custom providers

`ai.provider` (and a section's `provider`) accepts any string — not just the first-party ids. Key a custom provider's connection by its id in `ai.providerConfig` (`apiKey`, `baseUrl`, each bound to a name you choose with `env("…")`), put its model in `ai.language.model`, and AskDB hands them to whatever adapter is registered under that provider name.

```ts
import { defineConfig, env } from "@askdb/config";

export default defineConfig({
  ai: {
    provider: "mistral",           // any string
    providerConfig: {
      mistral: { apiKey: env("MISTRAL_API_KEY") },
    },
    language: { model: "mistral-large-latest" },
  },
  // ...
});
```

This works end to end only when the consuming registry has an adapter registered under that provider name. The built-in providers, registered by the first-party apps (`@askdb/http-api`, the CLI, Studio) and by default in `createAskDb`, are `openai`, `azure` (plus `azure-openai` and `foundry`), `google`, `anthropic`, and `gateway`. For any other provider you have two options:

1. **Embed AskDB** and pass your own adapter in `createAskDb({ providers: [myAdapter] })`. It takes about 40 lines of code. Add built-in names alongside it (`providers: ["openai", myAdapter]`) if you also want those.
2. **Use the `openai` provider** with a custom `baseUrl` for any OpenAI-compatible endpoint (vLLM, OpenRouter, Together, Ollama, …).

See [Bring your own model](/guides/bring-your-own-model/) for the embedding walkthrough.

## Reading config at runtime

In code that uses the AskDB libraries directly, call `bootstrapAskDbEnv()` at startup and then read settings via `getAskDbRuntimeConfig()`:

```ts
import { bootstrapAskDbEnv, getAskDbRuntimeConfig } from "@askdb/config";

bootstrapAskDbEnv({ cwd: process.cwd() });

const rt = getAskDbRuntimeConfig();
const aiEnv = rt.ai.aiEnv;                    // language model env map, for @askdb/ai
const embedding = rt.ai.embedding;            // { provider, connection, model, dimensions, env } when rag.embedder is "ai"
const outputDir = rt.introspection.outputDir; // resolved artifact directory
```

`rt.ai.language` and `rt.ai.embedding` each carry the section's resolved provider, connection name and model, plus an `env` map built from that section's connection only. To build the embedding model, pass `rt.ai.embedding.env` to `@askdb/ai`'s `createEmbeddingModelFromEnv`, with the configured width as an option, since the env map doesn't carry it:

```ts
import { createAiRegistry } from "@askdb/ai";

const embeddingModel = rt.ai.embedding
  ? await createAiRegistry().createEmbeddingModelFromEnv(rt.ai.embedding.env, {
      dimensions: rt.ai.embedding.dimensions, // undefined leaves the model's own width
    })
  : undefined; // rag.embedder is "mock"
```

AskDB does **not** copy the full config into `process.env`. The runtime snapshot is the source of truth — use `getAskDbRuntimeConfig` rather than `process.env` for anything AskDB-specific.

## Config precedence

For any given setting, the precedence (highest wins) is:

1. Per-call arguments — CLI flags (`--mode`, `--schema`, ...) and `ask()` options.
2. The `askdb.config.*` file — the single source of truth for the runtime snapshot.
3. Built-in defaults applied for optional fields (e.g. `outputDir` → `./askdb/`).

Environment variables don't override the config file from the outside — they flow *through* it: every `env("VAR")` call in the config reads the environment when the file loads. `.env` is loaded first (without overwriting variables already set in the real environment), so the per-environment override story is: system env beats `.env`, and whatever `env()` reads lands in the snapshot. This still lets you ship one config file and vary it per environment — just route each tunable through `env()`.
