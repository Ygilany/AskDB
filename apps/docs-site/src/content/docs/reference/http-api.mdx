<p class="doc-eyebrow">Reference · HTTP API</p>

<p class="doc-lede"><code>@askdb/http-api</code> is a thin HTTP wrapper around the same <code>ask()</code> pipeline as the library. Two endpoints, JSON over HTTP, designed to sit behind your own gateway.</p>

## Server

```ts
import { createAskDbHttpServer } from "@askdb/http-api";

const server = createAskDbHttpServer({
  port: 3000,
  host: "127.0.0.1",
  maxBodyBytes: 1024 * 1024,
});

server.listen();
```

| Option | Default | Description |
| --- | --- | --- |
| `port` | `3000` | Port to listen on. Config fallback: `httpApi.listen.port`. |
| `host` | `127.0.0.1` | Bind address. Bind to `0.0.0.0` only behind a gateway. Config fallback: `httpApi.listen.host`. |
| `schemaPath` | — | Server-default schema artifact path. Falls back to `host.schemaPath` in `askdb.config.ts`. |
| `maxBodyBytes` | `1048576` (1 MiB) | Request body size limit. Larger requests return `payload_too_large`. |

The server reads its schema and AI provider settings from `askdb.config.ts` via `@askdb/config` — see [Configuration](/reference/config/) for the resolution rules.

### Server config (`httpApi`)

These keys in `askdb.config.ts` control request handling. They apply to both `createAskDbHttpServer()` and the `askdb-http` binary.

| Key | Default | Description |
| --- | --- | --- |
| `httpApi.listen.port` / `httpApi.listen.host` | `3000` / `127.0.0.1` | Listen address when no `port` / `host` option or CLI flag is given. |
| `httpApi.allowSchemaOverride` | `false` | Accept a per-request `schemaJson` override. When `false`, a request that sends `schemaJson` gets `403 schema_override_disabled`. An override lets any caller put arbitrary schema text into the prompt through your model key, so enable it only for tests or trusted callers. |
| `httpApi.requestTimeoutMs` | `60000` | Abort the model call after this many milliseconds. A timed-out request returns `502 sql_generation_error`. Must be a positive integer. |
| `modes.omitSensitiveFromPrompt` | `false` | When `true`, sensitive identifiers are left out of every prompt. A request's `omitSensitiveFromPrompt: false` can't turn this off. |
| `modes.askdbMode` | `schema_only` | Mode used when the request sends neither `mode` nor `x-askdb-mode`. |

```ts
// askdb.config.ts
export default defineConfig({
  // ...
  httpApi: {
    listen: { port: 3000, host: "127.0.0.1" },
    allowSchemaOverride: false,
    requestTimeoutMs: 30_000,
  },
});
```

## Standalone binary

The package also ships an `askdb-http` binary, so you can run the service without writing any server code:

```bash
npx askdb-http --schema-path ./my-app.schema --port 3000 --host 127.0.0.1
```

| Flag | Description |
| --- | --- |
| `--schema-path <path>` | Server-default schema artifact path. |
| `--port <n>` | Port to listen on. |
| `--host <host>` | Bind address. |

Every flag is optional. Precedence per setting: CLI flag → `askdb.config.ts` (`host.schemaPath`, `httpApi.listen.port`, `httpApi.listen.host`) → built-in default.

If the server can't bind (for example, the port is already in use), `askdb-http` prints a one-line error and exits with code `1`.

## Endpoints

### `GET /health`

Liveness probe.

```bash
curl http://localhost:3000/health
```

```json
{ "ok": true }
```

### `POST /ask`

Generate SQL from a question.

**Request**

```json
{
  "question": "How many customers signed up last week?",
  "mode": "schema_only",
  "explain": false,
  "omitSensitiveFromPrompt": false,
  "schemaJson": "{\"version\":2, \"schemaId\":\"...\", \"tables\":[...]}"
}
```

| Field | Required | Default | Description |
| --- | --- | --- | --- |
| `question` | yes | — | The natural-language question. |
| `mode` | no | `modes.askdbMode`, else `schema_only` | One of `schema_only`, `bounded_results`. Also accepted as the `x-askdb-mode` header (the body wins). An unrecognized value returns `400 bad_request`. |
| `explain` | no | `false` | Return heuristic guardrail metadata. |
| `omitSensitiveFromPrompt` | no | `modes.omitSensitiveFromPrompt` | `true` omits sensitive columns from the prompt for this request. It can only tighten the server setting. When the server sets `modes.omitSensitiveFromPrompt: true`, sending `false` has no effect. |
| `schemaJson` | no | — | Inline schema artifact that replaces the server schema for this request. Rejected with `403 schema_override_disabled` unless the server sets `httpApi.allowSchemaOverride: true`. Preferred: set `host.schemaPath` in `askdb.config.ts` server-side. |

**Success response (`200`)**

```json
{
  "ok": true,
  "correlationId": "01H…",
  "sql": "SELECT count(*) FROM customers WHERE created_at >= …",
  "explain": null,
  "usage": {
    "promptTokens": 1250,
    "completionTokens": 45,
    "totalTokens": 1295
  },
  "sensitiveGuardrail": {
    "passed": true,
    "references": []
  }
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `sql` | `string` | The generated, validated SQL. |
| `explain` | `object \| null` | Heuristic guardrail metadata. Present (non-null) when `explain: true` was sent in the request. |
| `usage` | `object \| null` | Token counts for the generation call: `promptTokens`, `completionTokens`, `totalTokens` (each `number \| null`). `null` when the provider does not report usage. |
| `sensitiveGuardrail` | `object`, only on some responses | Present only when the schema marks at least one table or column `sensitive`. Shows which sensitive identifiers the returned `sql` references: `passed` (`boolean`), `references` (`{ table, schema?, column, matchKind }[]`), and `unresolvedScope` when the table scope couldn't be resolved. `passed: false` is a warning. The SQL is still returned, so check it before you execute. See [`validateSensitiveReferences`](/reference/core-api/#validatesensitivereferencessql-schema-options). |

**Error response (`4xx` / `5xx`)**

```json
{
  "ok": false,
  "correlationId": "01H…",
  "error": {
    "code": "sql_validation_error",
    "message": "Generated SQL contains a write statement.",
    "rule": "read_only"
  }
}
```

## Error codes

| Code | HTTP | When |
| --- | --- | --- |
| `not_found` | `404` | Unknown route. |
| `bad_request` | `400` | Malformed JSON, missing `question`, invalid `mode`, non-string `schemaJson`, a retired execution field, or no schema configured server-side. |
| `payload_too_large` | `413` | Body exceeds `maxBodyBytes`. |
| `schema_override_disabled` | `403` | The request sent `schemaJson` but `httpApi.allowSchemaOverride` is not `true`. |
| `schema_parse_error` | `400` | The schema artifact (inline `schemaJson` or the server's configured schema) couldn't be loaded or parsed. |
| `sql_validation_error` | `400` | Model output failed the SQL checks (must be a single `SELECT`/`WITH` statement, no comments, no write or DDL keywords, no blocked functions). Includes `rule`. |
| `guardrail_violation` | `422` | A tenant or sensitive-identifier guardrail rejected the generated SQL. Includes `rule`. |
| `generation_not_configured` | `500` | No model provider configured server-side. |
| `sql_generation_error` | `502` | The model call failed (provider error, or it hit `httpApi.requestTimeoutMs`). The message is generic. The provider's own error text is logged server-side and never returned. |
| `internal_error` | `500` | Anything else. The message is generic. The full error is logged server-side under the response's `correlationId`. |

The server picks the status code from the error's type, never from its message text. Every non-`2xx` response from `POST /ask` is logged as an `askdb.run.error` event with the status, code, and full error details, under the same `correlationId`.

## Correlation IDs

Every response includes a `correlationId`. The same ID is emitted in the server's structured log events, so you can join HTTP requests to generated SQL and any errors.

To carry a correlation ID supplied by your gateway, send the `x-correlation-id` header on the request — the server uses it as-is if present, otherwise generates one.

```bash
curl -X POST http://localhost:3000/ask \
  -H "content-type: application/json" \
  -H "x-correlation-id: req_abc123" \
  -d '{"question":"How many users?"}'
```

## What this server doesn't do

- **No auth.** Put your gateway in front.
- **No TLS termination.** Use your ingress.
- **No rate limiting.** Same.
- **No database connection.** It returns SQL; execution is your caller's responsibility.

See [Deploy as HTTP service](/guides/deploy-as-http-service/) for the production deployment pattern.
