# Architecture decision records

Read this index before changing code or reviewing a PR. Each Accepted row is a decision AskDB already made between viable options, and a Proposed row is one still under review in the PR it names; the ADR holds the options and why the others lost. Don't regress a decision silently: to change one, amend or supersede its ADR in the same PR.

A PR that adds an ADR adds its row here; a PR that amends or supersedes one updates its row.

| ADR | Status | Decision | Don't regress |
|---|---|---|---|
| [0001](0001-structured-logging-pino.md) Structured logging | Accepted | Pino, created through a small factory in core; logs are newline-delimited JSON. | CLI results go to stdout, diagnostics to stderr; `pino-pretty` is dev-only. |
| [0002](0002-integration-package-layout.md) Integration-package layout | Accepted (amended 2026-10) | One package per integration surface; `ask()` takes an `AskDialect`. The built-in `DialectSpec`s live in `@askdb/core`, which selects lexing and identifier quoting by `DialectSpec.id`; engine packages re-export their spec and own their connector, input shape and catalog queries. | No driver import or executor in core; `@askdb/introspect` stays engine-agnostic. |
| [0003](0003-postgres-partition-handling.md) Postgres partitions | Accepted | Partition leaves are filtered out in the Postgres catalog SQL; the partitioned parent is the canonical table. | Plain `INHERITS` children stay independent tables. |
| [0004](0004-enrichment-package-boundary.md) Enrichment boundary | Accepted (amended 2026-07) | `@askdb/enrich` is the headless authoring layer; Studio and custom surfaces depend on it. | Authoring logic lives in `@askdb/enrich`, not duplicated in Studio or the CLI. |
| [0005](0005-askdb-config-and-env-bootstrap.md) Config and env bootstrap | Accepted (amended 2026-10) | `@askdb/config` (`defineConfig`, `bootstrapAskDbEnv`) loads `.env` and `askdb.config.*` into an in-memory snapshot; `.config/askdb.*` is the alternate location. It also renders the `ai` block of a new config (`@askdb/config/scaffold`). | `@askdb/config` is the only package that reads `process.env`; apps get settings through `getAskDbRuntimeConfig()` (shell-only variables go through its small allowlist), and library packages take them from their host. The full config map is not merged into `process.env`. |
| [0006](0006-ai-provider-integration-strategy.md) AI provider integration | Accepted (amended 2026-09) | Core is BYO-model: `ask()` takes any AI SDK `LanguageModel`, and `ai` is a peer of core. `@askdb/ai` owns the provider registry, env precedence and the built-in providers, which load their SDKs lazily as optional peers; the `@askdb/ai-*` packages are deprecated re-export shims. | Core never depends on `@askdb/ai` or a provider SDK; `@askdb/ai`'s built-in providers and raw `LanguageModel`s are equally supported; no new code in the `@askdb/ai-*` shims. |
| [0007](0007-connector-registry.md) Connector registry | Accepted | `@askdb/connectors` holds the connector registry; engine packages export adapters and apps dispatch through the registry. | Apps don't re-implement per-engine switches. |
| [0009](0009-studio-local-api-protection.md) Studio local API protection | Accepted | Host allowlist on every request, same-origin and JSON checks, and a per-launch in-page session token (synchronizer token), not a Jupyter-style login token. | The token proves same-origin, not identity; keep the Host check, `no-store` and frame denial that its secrecy rests on. |
| [0010](0010-sql-guardrail-decision-point.md) SQL guardrail decision point | Accepted (implementation: #310) | Checks are pure rules over the model's SQL before rendering; one `decide()` maps findings and modes to a verdict. `ask()` acts on it at return, and `bindPreparedQuery()` re-runs the checks at rebind under the bind-time scope, rendering tenant IDs from that scope. No verdict is stored on `PreparedQuery`. | Modes are interpreted only in `decide`, not per path; a rebind never skips the tenant and sensitive checks or takes tenant IDs from `values`; `subtree` expansion stays in core at rebind too. |
| [0012](0012-sql-checks-are-defense-in-depth.md) SQL checks are defense in depth | Accepted | AskDB's SQL checks are a heuristic lint; the database (a read-only role, row-level security) is the security and tenant boundary. AskDB guarantees what it owns: scope required, `subtree` expansion, ID binding, and rendering that keeps the statement's structure. | Docs never present the checks as a security boundary; relaxing that wording supersedes this ADR and updates `docs/contracts/tenant-policy.md` in the same PR. |
| [0014](0014-subtree-scope-expands-per-root.md) Subtree scope expands per root | Accepted | A `subtree` scope expands through the host's `resolveTenantDescendants` into a per-root `multi_root` scope (`ids` when the subtree is one root table), in core. A covered level with no IDs stays in the scope with `ids: []`. | Never fold a subtree into one flat ID list or drop empty levels; each root keeps a distinct `:tenant_<name>_ids` placeholder. |
| [0015](0015-published-ranges-move-on-purpose.md) Published ranges move on purpose | Accepted (amended 2026-10) | A peer range moves only on purpose: a bump the range already allows moves only the lockfile, and a floor rises by hand for a needed feature, fix or security fix named in the changeset. The consumer lab pins the `ai` and `@ai-sdk/openai` floors. A package's own dependencies may move freely. | Raising an `ai` or `@ai-sdk/openai` floor raises the lab's host pin; AskDB's packages declare the same `ai` range for each AI SDK major. |
| [0016](0016-ai-config-connections-and-model-sections.md) AI config sections | Accepted | `ai.providerConfig.<provider>` holds provider connections only; the model choice lives in per-use sections `ai.language` and `ai.embedding`, with `ai.provider` as their default. Old keys are translated at load with a warning until 1.0. | One place per provider secret (no provider or key under `rag`); no layer picks an embedding model or keeps a table of model widths. |
| [0017](0017-sensitive-mentions-schema-wide.md) Sensitive mentions schema-wide | Accepted | Describable text is checked against one schema-wide list of sensitive names: a column marked sensitive itself by its bare name, a column sensitive only through its table only as `table.column`. | Don't scope the check per table; don't match table-inherited columns by bare name. |
| [0018](0018-ask-keeps-the-trailing-semicolon.md) `ask()` keeps the trailing semicolon | Accepted | `validateSelectSql` returns the model's statement trimmed and otherwise as written, keeping a single trailing `;`. Each SQL output keeps the `;` of the model block it comes from, and the parameterize consistency check ignores it. A host that wraps the statement removes the `;` first. | Core doesn't reshape the statement for one way of running it; any `;` other than one trailing `;` still throws `SQL_MULTI_STATEMENT`; remove the terminator with `/;$/` and `trimEnd`, never a pattern that starts `\s*`, which backtracks quadratically. |
| [0019](0019-test-gating-check-parses-with-typescript.md) Test-gating check parses with TypeScript | Proposed (#326) | `scripts/check-test-gating.mjs` parses each test file with `ts.createSourceFile` and applies its rules to the AST; a file that doesn't parse fails the check. | No regex or hand-lexed scan of test sources; the check never passes a file it couldn't read. |
