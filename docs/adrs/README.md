# Architecture decision records

Read this index before changing code or reviewing a PR. Each row is a decision AskDB already made between viable options; the ADR holds the options and why the others lost. Don't regress a decision silently: to change one, amend or supersede its ADR in the same PR.

A PR that adds an ADR adds its row here; a PR that amends or supersedes one updates its row.

| ADR | Status | Decision | Don't regress |
|---|---|---|---|
| [0001](0001-structured-logging-pino.md) Structured logging | Accepted | Pino, created through a small factory in core; logs are newline-delimited JSON. | CLI results go to stdout, diagnostics to stderr; `pino-pretty` is dev-only. |
| [0002](0002-integration-package-layout.md) Integration-package layout | Accepted (amended 2026-10; superseded in part by 0008 and 0029) | One package per integration surface; `ask()` takes a dialect id, a `DialectSpec` or a custom `AskDialect`. Where dialect rules live is ADR 0029's. | No driver import or executor in core; `@askdb/introspect` stays engine-agnostic. |
| [0003](0003-postgres-partition-handling.md) Postgres partitions | Accepted (amended 2026-10) | Partition leaves are filtered out in the Postgres catalog SQL; the partitioned parent is the canonical table. | Plain `INHERITS` children stay independent tables; foreign keys to or from a partition leaf (PG11+ clones) are dropped with the same `pg_inherits` predicate. |
| [0004](0004-enrichment-package-boundary.md) Enrichment boundary | Accepted (amended 2026-11) | `@askdb/enrich` is the headless authoring layer; Studio and custom surfaces depend on it. File access to a schema directory is core's (ADRs 0027 and 0028); the authoring workflow stays in enrich. | Authoring logic lives in `@askdb/enrich`, not duplicated in Studio or the CLI. |
| [0005](0005-askdb-config-and-env-bootstrap.md) Config and env bootstrap | Accepted (amended 2026-11) | `@askdb/config` (`defineConfig`, `bootstrapAskDbEnv`) loads `.env` and `askdb.config.*` into an in-memory snapshot; `.config/askdb.*` is the alternate location. The file exports a plain object or `defineConfig({ … })`, and both get the same checks. It also plans a new project for `askdb init` and Studio's setup wizard (`@askdb/config/scaffold`): the config source, `.env.example`, env vars and install plan, with the defaults left to the apps. `createAskDbHttpServer()` bootstraps when it is built, only if `isAskDbRuntimeInitialized()` is `false`; the snapshot is process-wide (`globalThis`), shared by every copy of `@askdb/config`. | `@askdb/config` is the only package that reads `process.env`, except `@askdb/ai`'s check of a provider SDK's own base URL variable (ADR 0036); apps get settings through `getAskDbRuntimeConfig()`, and library packages take them from their host. The flat `ASKDB_*` keys are internal; the one AskDB variable read from the environment is `ASKDB_DEBUG`. The full config map is not merged into `process.env`. `createAskDbHttpServer()` never reloads over a snapshot its host installed. |
| [0006](0006-ai-provider-integration-strategy.md) AI provider integration | Accepted (amended 2026-11) | Core is BYO-model: `ask()` takes any AI SDK `LanguageModel`, and `ai` is a peer of core. `@askdb/ai` owns the provider registry, env precedence and the built-in providers, which load their SDKs lazily as optional peers; the former `@askdb/ai-*` packages were removed before 1.0. Every package that depends on core declares core's `ai` peer, and the apps, which depend on `ai`, also depend on `zod` (#748). | Core never depends on `@askdb/ai` or a provider SDK; `@askdb/ai`'s built-in providers and raw `LanguageModel`s are equally supported. A package that depends on `@askdb/core` declares `ai`, and one that depends on `ai` or an `@ai-sdk/*` package declares `zod`, or Yarn Plug'n'Play can't resolve them (the installable smoke's `yarn-pnp.sh` checks both). |
| [0007](0007-connector-registry.md) Connector registry | Accepted (superseded in part by 0008; amended 2026-11; status note 2026-11-05, ADR 0029) | Engine packages export adapters and apps dispatch through a connector registry; since ADR 0008 the registry lives in `@askdb/introspect`, and `@askdb/connectors` was removed before 1.0. | Apps don't re-implement per-engine switches. |
| [0008](0008-engine-packages-and-connector-registry.md) Engine packages, the engine kit and the connector registry | Accepted (amended 2026-11) | One package per engine (driver peers and catalog SQL stay engine-local); the engine-agnostic mechanics (optional-driver loading, table filters, ids, row folding, connection labels) live once in `@askdb/introspect/kit`. The connector registry lives in `@askdb/introspect` with open provider ids, each adapter resolves its own connection (`resolveConnection`), and the `@askdb/connectors` shim was removed before 1.0. Since the 2026-11 amendment an entry can be lazy (`{ provider, load }`), for an optional engine package such as `@askdb/prisma`: `registry.load()` imports it once the engine is selected, and the other methods stay synchronous. | Don't copy kit helpers back into an engine; each engine writes its driver `import()` literally in its own package with `.catch(rethrowDriverImportError)` chained on it; apps never switch on the engine, and a third-party engine registers without an AskDB change. An unloaded lazy entry makes the synchronous methods throw rather than fall back, and hosts load only the selected engine. |
| [0009](0009-studio-local-api-protection.md) Studio local API protection | Accepted | Host allowlist on every request, same-origin and JSON checks, and a per-launch in-page session token (synchronizer token), not a Jupyter-style login token. | The token proves same-origin, not identity; keep the Host check, `no-store` and frame denial that its secrecy rests on. |
| [0010](0010-sql-guardrail-decision-point.md) SQL guardrail decision point | Accepted (stage (b): #310, PR #485; amended 2026-11 by 0023, 0024 and 0032, and by #698 and #702) | Checks are pure rules over the model's SQL before rendering; one `decide()` maps findings and modes to a verdict. `ask()` acts on it at return, and `bindPreparedQuery()` re-runs the checks at rebind under the bind-time scope, rendering tenant IDs from that scope. No verdict is stored on `PreparedQuery`. A custom `AskDialect` skips the read-only check, but with a tenant policy and any scope but `global` the tenant check refuses any statement that isn't a query (`NOT_SELECT_OR_WITH`), under every dialect. | Modes for findings about the SQL are interpreted only in `decide`, not per path (ADR 0023's load-time policy check is the one other reader of a policy's `enforcement`); a rebind never skips the tenant and sensitive checks or takes tenant IDs from `values`; `subtree` expansion stays in core at rebind too. Don't let a custom dialect's non-query pass the tenant check without amending this ADR. |
| [0011](0011-connection-labels-from-parsed-parts.md) Connection labels from parsed parts | Accepted | A connection label is built by `formatConnectionLabel` from the host, port and database (or file path) the engine adapter's `connectionLabelParts` parses, with the driver's own parser where there is one; anything that doesn't parse cleanly is `configured <engine> connection`. | Never build a label by masking secrets out of the raw string; adapters return parts, never label text; an `@` or `#` after a URL's host falls back. |
| [0012](0012-sql-checks-are-defense-in-depth.md) SQL checks are defense in depth | Accepted (amended 2026-11) | AskDB's SQL checks are a heuristic lint; the database (a read-only role, row-level security) is the security and tenant boundary. AskDB guarantees what it owns: scope required, `subtree` expansion, ID binding, and rendering that keeps the statement's structure. | Docs never present the checks as a security boundary; relaxing that wording supersedes this ADR and updates `docs/contracts/tenant-policy.md` in the same PR. Postgres `U&"…"` names stay refused by the read-only and tenant checks, not decoded (2026-11-06 amendment). An `E'…'` string continued on a later line, and a CockroachDB `b'…'` byte string with a backslash or a continuation, stay refused, not modeled (2026-11-06 amendments). |
| [0013](0013-table-filename-scheme.md) Table filenames | Accepted (amended 2026-11) | A new table's file is `<table>.md`, or `<schema>.<table>.md` when two names collide under a case-insensitive file-system comparison, from a filename-safe slug, shortened with a hash past 200 bytes; existing files keep their names. Every write into a schema directory goes through core's `saveSchemaFile()` (ADR 0028): it refuses a symbolic link and replaces the target through a temp file. | Pair files with tables by front-matter `id`, never by a computed filename; never write through a link or into an existing file in place. |
| [0014](0014-subtree-scope-expands-per-root.md) Subtree scope expands per root | Accepted | A `subtree` scope expands through the host's `resolveTenantDescendants` into a per-root `multi_root` scope (`ids` when the subtree is one root table), in core. A covered level with no IDs stays in the scope with `ids: []`. | Never fold a subtree into one flat ID list or drop empty levels; each root keeps a distinct `:tenant_<name>_ids` placeholder. |
| [0015](0015-published-ranges-move-on-purpose.md) Published ranges move on purpose | Accepted (amended 2026-10) | A peer range moves only on purpose: a bump the range already allows moves only the lockfile, and a floor rises by hand for a needed feature, fix or security fix named in the changeset. The consumer lab pins the `ai` and `@ai-sdk/openai` floors. A package's own dependencies may move freely. | Raising an `ai` or `@ai-sdk/openai` floor raises the lab's host pin; AskDB's packages declare the same `ai` range for each AI SDK major. |
| [0016](0016-ai-config-connections-and-model-sections.md) AI config sections | Accepted | `ai.providerConfig.<provider>` holds provider connections only; the model choice lives in per-use sections `ai.language` and `ai.embedding`, with `ai.provider` as their default. The old keys fail to load since #765, naming their replacements; each section reaches `@askdb/ai` typed, with no env view (#711). | One place per provider secret (no provider or key under `rag`); no layer picks an embedding model or keeps a table of model widths. |
| [0017](0017-sensitive-mentions-schema-wide.md) Sensitive mentions schema-wide | Accepted | Describable text is checked against one schema-wide list of sensitive names: a column marked sensitive itself by its bare name, a column sensitive only through its table only as `table.column`. | Don't scope the check per table; don't match table-inherited columns by bare name. |
| [0018](0018-ask-keeps-the-trailing-semicolon.md) `ask()` keeps the trailing semicolon | Accepted | `validateSelectSql` returns the model's statement trimmed and otherwise as written, keeping a single trailing `;`. Each SQL output keeps the `;` of the model block it comes from, and the parameterize consistency check ignores it. A host that wraps the statement removes the `;` first. | Core doesn't reshape the statement for one way of running it; any `;` other than one trailing `;` still throws `SQL_MULTI_STATEMENT`; remove the terminator with `/;$/` and `trimEnd`, never a pattern that starts `\s*`, which backtracks quadratically. |
| [0019](0019-loader-fails-closed-on-schema-directory-json.md) Loader fails closed on a stray schema JSON | Accepted (amended 2026-11) | `loadSchema()` matches `schema.json` in any case and loads its directory. Any other JSON file that isn't a bundle throws `SchemaParseError` when `tenant-policy.md`, `tables/` or `concepts.md` sits beside it, in any case. | A JSON file inside a schema directory never loads without its siblings; no warning-only fallback, and the name match stays case-insensitive. |
| [0021](0021-tenant-policy-draft-follows-ask-sensitivity.md) Tenant-policy draft and sensitive columns | Accepted | Studio's **Draft with AI** builds its prompt from `loadSchema()` with core's `formatSchemaV2ForNlToSql`: sensitive columns tagged by default and withheld under `modes.omitSensitiveFromPrompt`, no describable text, untracked tables left out. A foreign key is sent only when both columns are listed; withheld keys come back as Studio-written `warnings`. | Don't render the draft's schema outside core's formatter or always withhold regardless of the mode; never write the withheld-key notice into the draft body. When core prints foreign keys (#349), delete Studio's foreign-key block. |
| [0022](0022-omission-withholds-mentions-in-prompts.md) Omission withholds mentions in prompts | Accepted | With `omitSensitiveIdentifiersFromNlToSqlPrompt`, both NL→SQL prompt builders withhold describable text that names a sensitive column (ADR 0017's list from `sensitiveMentionNames`, in the chunker's units). The retrieval prompt also withholds the text of any chunk flagged `sensitive: true`; a withheld chunk still picks its tables. | Don't trust the retriever or the index to have filtered; don't redact inside a sentence; keep one owner of the name list in `@askdb/core`. |
| [0023](0023-tenant-policy-problems-fail-strict-loads.md) Tenant policy problems fail strict loads | Accepted | Under `enforcement: strict`, a tenant policy with an orphaned column or foreign key ID, a hierarchy cycle or an undeclared root makes `loadSchema()` throw `SchemaParseError`. Under `warn` they load as `warnings`. A removed table's entry is one warning in both modes. `ask()` logs `askdb.tenant.policy_warnings` once per loaded schema; `askdb introspect --out` prints the problems. | Don't load a strict policy with these errors, or turn a removed table into an error; keep the check in `normalizeTenantPolicy` so every loader and Studio's Save share it. |
| [0024](0024-tenant-ids-leave-the-sql-text.md) Tenant IDs leave the SQL text | Accepted (amended 2026-11) | The default `tenantSqlMode` is `sql-params` (`DEFAULT_TENANT_SQL_MODE`): tenant IDs are driver parameters. A custom `AskDialect`, or a `DialectSpec` whose `id` isn't built in, has no default with a tenant scope and must set the mode (`TENANT_SQL_MODE_REQUIRED`). A rebind takes `tenantSqlMode` with the same default (#664). The mode governs `sql` only: `unboundSql` always binds tenant IDs, with them in `params` (#731). Wherever AskDB inlines a tenant ID (`sql-only` `sql`, in `ask()` or a rebind), the ID must be printable ASCII without a backslash, on every dialect (`UNESCAPABLE_TENANT_ID`), and only quotes are doubled. Business values a rebind inlines keep the dialect-match condition (#340). | Don't make inlining the default again, inline tenant IDs into `unboundSql` in any mode, give a custom dialect a guessed marker style, or escape rather than refuse a tenant ID outside the allowlist; hosts import `DEFAULT_TENANT_SQL_MODE` rather than hard-code the mode. |
| [0025](0025-config-mode-is-the-loosest-a-call-gets.md) Config mode is the loosest a call gets | Accepted | `@askdb/client` runs the stricter of the call's `mode` and config `modes.askdbMode` (unset: `schema_only`). A looser request runs at the config mode with no error. The CLI and the HTTP API pass only the caller's mode. | Don't let a per-call or per-request mode loosen the config; don't resolve the mode again in a host. |
| [0026](0026-every-prompt-follows-omission.md) Every prompt follows omission | Accepted (amended 2026-11) | `modes.omitSensitiveFromPrompt` applies to every prompt sent to a language model: Studio's Playground passes it to `ask()`, and enrichment suggestions read `loadSchema()`'s effective flags and list the target table with `formatSchemaV2ForNlToSql`, refusing a sensitive column as the target (`SensitiveEnrichmentTargetError`). Core's `EnrichmentTarget` and `EnrichmentContext` take `NormalizedV2Table`, so a raw `schema.json` table doesn't compile as a target. The tenant policy block is the one exception: it keeps naming the tenant columns the policy lists. | Don't add a prompt that skips the setting or renders schema outside core's formatter; don't widen `EnrichmentTarget.table` or `EnrichmentContext.neighbors` back to `V2Table`; don't withhold tenant columns from the tenant block without superseding this ADR. |
| [0027](0027-core-reads-schema-directory-with-exact-names.md) Core reads a schema directory, names exact | Accepted | `readSchemaDirectory()` in core reads a schema directory for `loadSchema()` and `bundleSchemaDirectory()`. A name it looks up (`schema.json`, `tenant-policy.md`, `concepts.md`, `tables/`, `.md` in `tables/`) must be spelled exactly; a wrong-case one throws `SchemaParseError` on every OS. A path the caller passes is read as given. | Never skip or accept a wrong-case schema file; never copy the directory read into another package. |
| [0028](0028-core-writes-schema-directory-files.md) Core writes schema-directory files | Accepted | `saveSchemaFile(schemaDir, relativePath, content)` in `@askdb/core` writes a file into a schema directory for enrich's saves, Studio's Playground history and `.gitignore`, and introspect's `schema.json`. It refuses a symbolic link at the file or at a directory below the schema directory, and a path with an empty, `.` or `..` part, and replaces the target through a temp file. | Never write a schema-directory file in place (`writeFileSync` or `appendFileSync` on the target) or keep a second copy of the rules in another package; change part of a file by reading it and saving the whole file. |
| [0029](0029-core-owns-built-in-dialect-specs.md) Core owns the built-in dialect specs | Accepted (amended 2026-11 by 0032) | `@askdb/core` owns the six built-in `DialectSpec`s and their rules (prompt brief, forbidden keywords and functions, list binding, escaping and quoting, namespace rules, reserved words) and resolves string ids, so `ask({ dialect: "postgres" })` needs only core. Engine packages own drivers, connectors and catalog SQL, re-export the specs, and check their spec's reserved words against the fixture's server. | Core never imports an engine package to resolve an id (that is a cycle); don't move the specs or open `DialectId` before 1.0 without a new ADR; a reserved word the server rejects bare goes in core's list. |
| [0030](0030-1-0-promises-checked-sql-only.md) 1.0 promises checked SQL only | Accepted (amended 2026-11) | 1.0 promises checked SQL from the library, the CLI and the HTTP API; reports, result summaries, a non-stub `bounded_results` and MCP come after 1.0. Core, client, config, ai, `askdb`, http-api, introspect and the engine packages go to 1.0.0; Studio, enrich and rag stay 0.x, and the `studio` and `rag` config blocks, the `askdb studio`, `enrich`, `bundle` and `rag` commands, `askdb init`'s RAG and Studio flags, and `@askdb/config/scaffold` are experimental. | Don't present reports, summaries or MCP as 1.0 features; a breaking change to the 1.0 set outside its experimental surfaces needs a major version, and a breaking change to an experimental surface releases `askdb` or `@askdb/config` as at least a minor. |
| [0031](0031-unused-exports-leave-before-1-0.md) Unused exports leave before 1.0 | Accepted | Before 1.0, a dropped public export that nothing in the repo calls and no page documents is removed in one step with a minor changeset, not deprecated first; which ones to drop is decided per export. Engine catalog SQL is internal; only `@askdb/postgres` exports its templates, because its from-export mode has a person run them. | Don't re-export MySQL, SQLite or SQL Server catalog SQL from a package entry without a from-export mode that needs it; tests read it from `connector/describe.ts`. |
| [0032](0032-rebind-checks-under-the-hosts-dialect-spec.md) A rebind uses the host's dialect rules | Accepted | `ask()` records `preparedQuery.dialectRules` (`"builtin"` for a built-in id or the exported constant, `"host"` for any other `DialectSpec` object). `bindPreparedQuery()` checks and renders under `guardrails.dialect`, which a `"host"` template, or one stored without `dialectRules`, must pass (`DIALECT_SPEC_REQUIRED`); a built-in id is enough for the built-in rules. | Don't fall back to the built-in spec for a template whose rules AskDB can't recover; don't guess from the artifact's `dialect` id alone. |
| [0033](0033-error-codes-nothing-throws-leave-before-1-0.md) Error codes nothing reports leave before 1.0 | Accepted | Before 1.0, a member of a public error-code union that none of AskDB's own code paths reports is removed with a minor changeset, unless its rule is cheap to enforce now, when it is thrown instead; decided per code. `GLOBAL_WITHOUT_REASON` is thrown by `validateTenantScope()` before the shape check; `INCOMPATIBLE_JOIN_SCOPES`, `CROSS_TENANT_WITHOUT_GLOBAL`, `INVALID_NAME` and `RESERVED_NAME` were removed. | Don't add a code to a public union without the check that reports it; docs-site `test:errors` keeps `errors.ts` and the reference Errors tables in step both ways. |
| [0034](0034-docs-diagrams-are-d2-rendered-at-build-time.md) Docs diagrams are D2 | Accepted | Docs-site diagrams are D2 source rendered to inline SVG at build time by `astro-d2` with D2's WebAssembly build; `custom.css` maps D2's palette to Starlight's color variables so a diagram follows the theme toggle. | Don't add a diagram tool that needs a binary or a browser in CI or the Pages deploy, or one that ships diagram JavaScript to readers; don't hard-code colors in a `.d2` file. |
| [0036](0036-model-base-urls-with-credentials-are-refused.md) Model base URLs with credentials are refused | Accepted | A model base URL with a user name or password is refused where AskDB reads it: at config load (an `askdb.config:` error naming the key, for every `ai.providerConfig.*.baseUrl`) and in `@askdb/ai` (`AiBaseUrlCredentialsError`, whose `setting` names the env variable, `connection.baseUrl`, `baseURL`, or the SDK's own `OPENAI_BASE_URL`/`ANTHROPIC_BASE_URL`). | No message repeats the URL; credentials are never masked out of a failure's text (ADR 0011's reasoning). A new built-in provider builds its SDK options through `baseURLOption()`. |
| [0037](0037-introspection-refuses-an-empty-artifact.md) Introspection refuses an empty artifact | Accepted | `renderSchemaV2Body()` throws `EmptyIntrospectionError` when the rendered table list is empty (an empty database, an enums-only Postgres schema, filters that match nothing), before any merge or write; `askdb introspect` exits `1` and Studio answers `422`. | Never write a `schema.json` with `tables: []`; check the rendered tables, not `isEmpty`; the message names the schema id, engine and filters, never the connection. The Schema v2 contract keeps requiring a table. |
| [0038](0038-prompt-hints-name-no-schema-table.md) Prompt hints name no schema table | Accepted | The NL→SQL prompt's ambiguity hints name no table from the schema: the unknown-name note repeats only the question's word, and the single-table note names no table. Both count tracked tables only. | Never list schema tables in a hint: the DDL already carries every table the model may use, and a list can name an untracked or unretrieved one. |
