# Architecture decision records

Read this index before changing code or reviewing a PR. Each row is a decision AskDB already made between viable options; the ADR holds the options and why the others lost. Don't regress a decision silently: to change one, amend or supersede its ADR in the same PR.

A PR that adds an ADR adds its row here; a PR that amends or supersedes one updates its row.

| ADR | Status | Decision | Don't regress |
|---|---|---|---|
| [0001](0001-structured-logging-pino.md) Structured logging | Accepted | Pino, created through a small factory in core; logs are newline-delimited JSON. | CLI results go to stdout, diagnostics to stderr; `pino-pretty` is dev-only. |
| [0002](0002-integration-package-layout.md) Integration-package layout | Accepted (amended 2026-10) | One package per integration surface; `ask()` takes an `AskDialect`. The built-in `DialectSpec`s live in `@askdb/core`, which selects lexing and identifier quoting by `DialectSpec.id`; engine packages re-export their spec and own their connector, input shape and catalog queries. | No driver import or executor in core; `@askdb/introspect` stays engine-agnostic. |
| [0003](0003-postgres-partition-handling.md) Postgres partitions | Accepted (amended 2026-10) | Partition leaves are filtered out in the Postgres catalog SQL; the partitioned parent is the canonical table. | Plain `INHERITS` children stay independent tables; foreign keys to or from a partition leaf (PG11+ clones) are dropped with the same `pg_inherits` predicate. |
| [0004](0004-enrichment-package-boundary.md) Enrichment boundary | Accepted (amended 2026-07) | `@askdb/enrich` is the headless authoring layer; Studio and custom surfaces depend on it. | Authoring logic lives in `@askdb/enrich`, not duplicated in Studio or the CLI. |
| [0005](0005-askdb-config-and-env-bootstrap.md) Config and env bootstrap | Accepted (amended 2026-11) | `@askdb/config` (`defineConfig`, `bootstrapAskDbEnv`) loads `.env` and `askdb.config.*` into an in-memory snapshot; `.config/askdb.*` is the alternate location. It also renders the `ai` block of a new config (`@askdb/config/scaffold`). | `@askdb/config` is the only package that reads `process.env`; apps get settings through `getAskDbRuntimeConfig()`, and library packages take them from their host. The flat `ASKDB_*` keys are internal; the one AskDB variable read from the environment is `ASKDB_DEBUG`. The full config map is not merged into `process.env`. |
| [0006](0006-ai-provider-integration-strategy.md) AI provider integration | Accepted (amended 2026-11) | Core is BYO-model: `ask()` takes any AI SDK `LanguageModel`, and `ai` is a peer of core. `@askdb/ai` owns the provider registry, env precedence and the built-in providers, which load their SDKs lazily as optional peers; the former `@askdb/ai-*` packages were removed before 1.0. | Core never depends on `@askdb/ai` or a provider SDK; `@askdb/ai`'s built-in providers and raw `LanguageModel`s are equally supported. |
| [0007](0007-connector-registry.md) Connector registry | Accepted (superseded in part by 0008; amended 2026-11) | Engine packages export adapters and apps dispatch through a connector registry; since ADR 0008 the registry lives in `@askdb/introspect`, and `@askdb/connectors` was removed before 1.0. | Apps don't re-implement per-engine switches. |
| [0008](0008-engine-packages-and-connector-registry.md) Engine packages, the engine kit and the connector registry | Accepted (amended 2026-11) | One package per engine (driver peers and catalog SQL stay engine-local); the engine-agnostic mechanics (optional-driver loading, table filters, ids, row folding, connection labels) live once in `@askdb/introspect/kit`. The connector registry lives in `@askdb/introspect` with open provider ids, each adapter resolves its own connection (`resolveConnection`), and the `@askdb/connectors` shim was removed before 1.0. | Don't copy kit helpers back into an engine; each engine writes its driver `import()` literally in its own package with `.catch(rethrowDriverImportError)` chained on it; apps never switch on the engine, and a third-party engine registers without an AskDB change. |
| [0009](0009-studio-local-api-protection.md) Studio local API protection | Accepted | Host allowlist on every request, same-origin and JSON checks, and a per-launch in-page session token (synchronizer token), not a Jupyter-style login token. | The token proves same-origin, not identity; keep the Host check, `no-store` and frame denial that its secrecy rests on. |
| [0010](0010-sql-guardrail-decision-point.md) SQL guardrail decision point | Accepted (stage (b): #310, PR #485) | Checks are pure rules over the model's SQL before rendering; one `decide()` maps findings and modes to a verdict. `ask()` acts on it at return, and `bindPreparedQuery()` re-runs the checks at rebind under the bind-time scope, rendering tenant IDs from that scope. No verdict is stored on `PreparedQuery`. | Modes are interpreted only in `decide`, not per path; a rebind never skips the tenant and sensitive checks or takes tenant IDs from `values`; `subtree` expansion stays in core at rebind too. |
| [0011](0011-connection-labels-from-parsed-parts.md) Connection labels from parsed parts | Accepted | A connection label is built by `formatConnectionLabel` from the host, port and database (or file path) the engine adapter's `connectionLabelParts` parses, with the driver's own parser where there is one; anything that doesn't parse cleanly is `configured <engine> connection`. | Never build a label by masking secrets out of the raw string; adapters return parts, never label text; an `@` or `#` after a URL's host falls back. |
| [0012](0012-sql-checks-are-defense-in-depth.md) SQL checks are defense in depth | Accepted (amended 2026-11) | AskDB's SQL checks are a heuristic lint; the database (a read-only role, row-level security) is the security and tenant boundary. AskDB guarantees what it owns: scope required, `subtree` expansion, ID binding, and rendering that keeps the statement's structure. | Docs never present the checks as a security boundary; relaxing that wording supersedes this ADR and updates `docs/contracts/tenant-policy.md` in the same PR. |
| [0013](0013-table-filename-scheme.md) Table filenames | Accepted (amended 2026-11) | A new table's file is `<table>.md`, or `<schema>.<table>.md` when two names collide under a case-insensitive file-system comparison, from a filename-safe slug, shortened with a hash past 200 bytes; existing files keep their names. Every `@askdb/enrich` save into the schema directory (`tables/*.md`, `concepts.md`, `tenant-policy.md`) refuses a symbolic link and replaces the target through a temp file. | Pair files with tables by front-matter `id`, never by a computed filename; never write through a link or into an existing file in place. |
| [0014](0014-subtree-scope-expands-per-root.md) Subtree scope expands per root | Accepted | A `subtree` scope expands through the host's `resolveTenantDescendants` into a per-root `multi_root` scope (`ids` when the subtree is one root table), in core. A covered level with no IDs stays in the scope with `ids: []`. | Never fold a subtree into one flat ID list or drop empty levels; each root keeps a distinct `:tenant_<name>_ids` placeholder. |
| [0015](0015-published-ranges-move-on-purpose.md) Published ranges move on purpose | Accepted (amended 2026-10) | A peer range moves only on purpose: a bump the range already allows moves only the lockfile, and a floor rises by hand for a needed feature, fix or security fix named in the changeset. The consumer lab pins the `ai` and `@ai-sdk/openai` floors. A package's own dependencies may move freely. | Raising an `ai` or `@ai-sdk/openai` floor raises the lab's host pin; AskDB's packages declare the same `ai` range for each AI SDK major. |
| [0016](0016-ai-config-connections-and-model-sections.md) AI config sections | Accepted | `ai.providerConfig.<provider>` holds provider connections only; the model choice lives in per-use sections `ai.language` and `ai.embedding`, with `ai.provider` as their default. Old keys are translated at load with a warning until 1.0. | One place per provider secret (no provider or key under `rag`); no layer picks an embedding model or keeps a table of model widths. |
| [0017](0017-sensitive-mentions-schema-wide.md) Sensitive mentions schema-wide | Accepted | Describable text is checked against one schema-wide list of sensitive names: a column marked sensitive itself by its bare name, a column sensitive only through its table only as `table.column`. | Don't scope the check per table; don't match table-inherited columns by bare name. |
| [0018](0018-ask-keeps-the-trailing-semicolon.md) `ask()` keeps the trailing semicolon | Accepted | `validateSelectSql` returns the model's statement trimmed and otherwise as written, keeping a single trailing `;`. Each SQL output keeps the `;` of the model block it comes from, and the parameterize consistency check ignores it. A host that wraps the statement removes the `;` first. | Core doesn't reshape the statement for one way of running it; any `;` other than one trailing `;` still throws `SQL_MULTI_STATEMENT`; remove the terminator with `/;$/` and `trimEnd`, never a pattern that starts `\s*`, which backtracks quadratically. |
| [0019](0019-loader-fails-closed-on-schema-directory-json.md) Loader fails closed on a stray schema JSON | Accepted | `loadSchema()` matches `schema.json` in any case and loads its directory. Any other JSON file that isn't a bundle throws `SchemaParseError` when `tenant-policy.md`, `tables/` or `concepts.md` sits beside it. | A JSON file inside a schema directory never loads without its siblings; no warning-only fallback, and the name match stays case-insensitive. |
| [0021](0021-tenant-policy-draft-follows-ask-sensitivity.md) Tenant-policy draft and sensitive columns | Accepted | Studio's **Draft with AI** builds its prompt from `loadSchema()` with core's `formatSchemaV2ForNlToSql`: sensitive columns tagged by default and withheld under `modes.omitSensitiveFromPrompt`, no describable text, untracked tables left out. A foreign key is sent only when both columns are listed; withheld keys come back as Studio-written `warnings`. | Don't render the draft's schema outside core's formatter or always withhold regardless of the mode; never write the withheld-key notice into the draft body. When core prints foreign keys (#349), delete Studio's foreign-key block. |
| [0022](0022-omission-withholds-mentions-in-prompts.md) Omission withholds mentions in prompts | Accepted | With `omitSensitiveIdentifiersFromNlToSqlPrompt`, both NL→SQL prompt builders withhold describable text that names a sensitive column (ADR 0017's list from `sensitiveMentionNames`, in the chunker's units). The retrieval prompt also withholds the text of any chunk flagged `sensitive: true`; a withheld chunk still picks its tables. | Don't trust the retriever or the index to have filtered; don't redact inside a sentence; keep one owner of the name list in `@askdb/core`. |
| [0025](0025-config-mode-is-the-loosest-a-call-gets.md) Config mode is the loosest a call gets | Accepted | `@askdb/client` runs the stricter of the call's `mode` and config `modes.askdbMode` (unset: `schema_only`). A looser request runs at the config mode with no error. The CLI and the HTTP API pass only the caller's mode. | Don't let a per-call or per-request mode loosen the config; don't resolve the mode again in a host. |
